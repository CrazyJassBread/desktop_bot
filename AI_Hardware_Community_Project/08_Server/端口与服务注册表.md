# 端口与服务注册表

> 本文件是端口分配的唯一事实源。新增服务必须先在此登记，再修改 Compose、Helm、Nginx 和防火墙。  
> 原则：容器内使用服务默认端口；宿主机开发映射使用项目专属 `18000–18999`；生产只开放公网入口。

## 1. 端口策略

### 生产公网允许

| 端口 | 协议 | 服务 | 说明 |
|---:|---|---|---|
| 80 | TCP/HTTP | Nginx/Ingress | 只重定向到 443 |
| 443 | TCP/HTTPS/WSS | Nginx/Ingress | Web、REST、SSE、浏览器 WebSocket |
| 8883 | TCP/MQTTS | MQTT Broker/LB | Phase 3 设备直连；未启用设备前不开放 |

可选的 MQTT over WebSocket 应复用 443 路径（例如 `/mqtt`），不额外公开 8083。管理端口、数据库、Redis、MinIO Console、监控面板均不得直接暴露公网。

### 宿主机专属号段

| 号段 | 归属 |
|---|---|
| 18000–18099 | Web 与核心业务服务 |
| 18100–18199 | AI、Agent、Voice |
| 18200–18299 | IoT、设备、MQTT 开发映射 |
| 18300–18399 | 数据与存储开发映射 |
| 18400–18499 | 可观测性与运维 |
| 18500–18599 | 本地开发辅助工具 |
| 18600–18799 | 后续业务应用预留 |
| 18800–18899 | 第三方集成与 Webhook 预留 |
| 18900–18999 | 临时迁移/灾备演练；禁止长期占用 |

此号段是项目约定，不代表操作系统自动保留。部署脚本仍需在启动前检测实际占用。

## 7. 环境变量

宿主机映射必须可覆盖：

```dotenv
WEB_HOST_PORT=18000
API_HOST_PORT=18010
REALTIME_HOST_PORT=18020
AGENT_RUNTIME_HOST_PORT=18100
VOICE_RUNTIME_HOST_PORT=18110
POSTGRES_HOST_PORT=18300
REDIS_CACHE_HOST_PORT=18310
REDIS_QUEUE_HOST_PORT=18311
MINIO_API_HOST_PORT=18320
MINIO_CONSOLE_HOST_PORT=18321
GRAFANA_HOST_PORT=18400
```

服务间 URL 使用容器 DNS，不使用宿主机端口：

```dotenv
DATABASE_URL=postgresql://...@postgres:5432/community
REDIS_CACHE_URL=redis://redis-cache:6379
S3_ENDPOINT=http://minio:9000
AGENT_RUNTIME_URL=http://agent-runtime:8000
```

## 8. Compose 绑定规则

local 可绑定到 loopback，避免局域网暴露：

```yaml
ports:
  - "127.0.0.1:${POSTGRES_HOST_PORT:-18300}:5432"
```

production 的数据库、Redis、Runtime、监控等不写 `ports`，只写 `expose`/容器网络。只有反向代理和启用后的 MQTTS 负载均衡器发布宿主机端口。

## 9. 冲突检查与登记流程

启动前：

1. 从 `.env` 解析所有将发布的宿主机端口；
2. 检查端口是否重复；
3. 使用 `Get-NetTCPConnection`/`netstat` 检查宿主机占用；
4. 若冲突，停止启动并输出“端口、占用进程、建议备用端口”；
5. 修改本注册表和环境配置，不能只临时改 Compose；
6. CI 验证 Compose/Helm/本文登记一致。

Windows 检查示例：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -ge 18000 -and $_.LocalPort -le 18999 } |
  Sort-Object LocalPort |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

Linux 检查示例：

```bash
ss -lntup
```

## 10. 防火墙基线

- 入站默认拒绝；
- 公网只允许 80/443，以及 Phase 3 明确启用的 8883；
- SSH/运维入口限制源 IP、VPN 或零信任网络；
- 数据库/Redis/MinIO/Qdrant/监控只允许应用私网/运维身份；
- Agent Tool Executor 出站默认拒绝，按工具 allowlist 放行；
- MQTT Broker 管理 API 与客户端端口分离，管理 API 不公开；
- 端口开放变更必须有工单/审计和回收日期。

## 11. 命名与服务发现

- Compose 服务名固定：`web`、`core-api`、`postgres`、`redis-cache` 等；
- Kubernetes Service 使用相同语义命名；
- 不在业务代码硬编码 IP/宿主机端口；
- 所有健康检查通过服务名与容器端口；
- 外部域名建议：
  - `example.com`：Web
  - `api.example.com`：API（也可同域 `/api`）
  - `assets.example.com`：CDN
  - `mqtt.example.com:8883`：设备
  - `status.example.com`：状态页
