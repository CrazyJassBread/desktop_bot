# 后端服务设计

## 1. 技术选择

核心业务使用 NestJS + TypeScript，ORM 推荐 Prisma（迁移需审查 SQL）或 Drizzle；两者只选一个。本文以 NestJS 分层和 PostgreSQL 为基线，不依赖特定 ORM API。

Agent/Voice 使用 Python 3.11+ + FastAPI：

- `agent-runtime` 适配模型、工具、RAG 和长任务；
- `voice-runtime` 封装现有 `desktop_bot` 的 `VoicePipeline`；
- Core API 是权限、配额和业务事实源，Runtime 不直接修改社区核心表。

## 2. 工程分层

```text
src/modules/content/
├─ domain/          # Entity、Value Object、领域规则、事件
├─ application/     # Use case、Command/Query、Port
├─ infrastructure/  # Repository、ORM mapper、外部适配
├─ presentation/    # Controller、DTO、Guard
└─ content.module.ts
```

避免为了形式复制大量空层。复杂领域（身份、内容、Agent、设备）完整分层；简单后台配置可采用薄服务。

## 3. 核心模块

### Identity

- 邮箱标准化后唯一；
- 密码 Argon2id；
- 登录失败按账号/IP 组合限流，但不暴露账号是否存在；
- Access Token 10–15 分钟；
- Refresh Token 7–30 天，旋转并检测 reuse；同 family 被重用则撤销整个 family；
- Session 列表支持设备名、最近 IP 粗粒度位置、最后活跃和撤销；
- 邮箱验证、密码重置 token 只存哈希；
- 管理员 MFA 和重新认证预留。

### Users

- `users` 存账号业务主体，`user_profiles` 存公开资料；
- username 规范化、保留字和改名冷却；
- follow 唯一约束，禁止自关注；
- 统计值异步维护，定期校准；
- 创作者认证采用申请与审核记录，不直接写角色。

### Content

状态机：

```text
draft -> pending_review -> published -> archived
   |           |              |
   +---------->rejected       +-> removed
```

公开发布权限和是否先审后发由用户信任级别/内容风险决定。每次保存带 `version`，SQL 更新需匹配旧 version；0 行表示冲突。重要发布版本写 `content_revisions`。

### Social

- reaction 先只支持 `like`，表结构可扩展但 UI 不滥用；
- bookmark 可带 collection（MVP 可只用默认收藏夹）；
- 评论最大 2 层展示；数据库保存 materialized path 或 `root_id/parent_id`；
- 删除有回复的评论保留占位和结构；
- 计数由事务内增减或事件异步更新，夜间校准。

### Files

状态：`initiated -> uploaded -> scanning -> ready|rejected|deleted`。

创建上传意图时检查用户配额、允许 MIME、大小；完成时使用对象存储 HEAD 校验真实大小，并由 Worker 计算/复核哈希和 magic bytes。公开引用只允许 `ready` 文件。

### Search

写入由 Outbox 消费；读模型包含权限过滤字段。MVP PostgreSQL 查询：

- `websearch_to_tsquery` 全文；
- `pg_trgm` 用户名/标题模糊；
- rank 综合文本相关度、时间衰减、质量分和互动对数。

不得把简单热度直接做成浏览量排序，否则易被刷。

### Notifications

创建通知前检查偏好；同类短时聚合，如“5 人赞了你的项目”。站内通知事实落库，WebSocket 只是传输。邮件通过队列，模板版本化，退订链接签名。

### Moderation

举报状态：`open -> triaged -> investigating -> resolved|dismissed`。处罚必须记录操作者、原因、规则条款、证据摘要和可选到期时间。AI 可做风险排序，最终处罚由规则或人工确认。

### Agent Control

- Agent 元数据、版本、权限声明、发布状态；
- 创建 Run 前验证所有权/公开性、版本、预算和工具 scope；
- 生成短期 Runtime Capability Token；
- 接收 Runtime 状态回调并验签；
- 用量与成本不可只依赖客户端上报。

### Device Control

- 注册型号、设备、绑定挑战、凭证状态；
- MQTT ACL 从设备身份派生；
- 命令记录先落库再投递，ACK 更新状态；
- Device Shadow 拆 desired/reported；
- OTA 策略、批次、失败阈值和回滚。

## 4. REST 约定

- 资源名复数：`/api/v1/contents`；
- `POST` 创建，`GET` 读取，`PATCH` 部分更新，`DELETE` 语义删除；
- 关系状态用幂等 `PUT /contents/{id}/like` 与 `DELETE`；
- 列表使用 cursor，不用深 offset；
- 创建/发布/命令等支持 `Idempotency-Key`；
- 写响应返回新 `version` 和 `updated_at`；
- API 时间统一 RFC3339 UTC，金额用最小货币单位整数，ID 用字符串。

## 5. 错误模型

```json
{
  "error": {
    "code": "CONTENT_VERSION_CONFLICT",
    "message": "内容已在其他位置更新",
    "details": [{"field": "version", "reason": "stale"}],
    "request_id": "req_...",
    "retryable": false
  }
}
```

错误 code 稳定，message 可本地化。异常过滤器映射领域错误，未知异常只返回通用消息并记录内部 stack。

## 6. 事务与一致性

强一致：账号唯一性、权限、内容状态转换、配额扣减、Agent 预算预留、设备绑定。

最终一致：计数、搜索索引、通知聚合、推荐、在线状态。

跨模块副作用采用 Transactional Outbox：

1. 业务数据与 outbox 同事务；
2. Publisher 轮询/CDC 发布；
3. 消费者以 `event_id` 去重；
4. 超过重试进入 DLQ，后台可重放；
5. 事件 payload 不包含不必要的 PII。

## 7. 队列

| 队列 | 任务 | 建议并发/超时 |
|---|---|---|
| `file-scan` | MIME、AV、解压检查 | CPU/IO 隔离，5 min |
| `image-process` | 缩略图、转码、元数据 | 30–120 sec |
| `search-index` | upsert/delete 索引 | 高并发、短任务 |
| `notification` | 站内聚合/邮件 | 限速 |
| `agent-run` | Agent 调度 | 按用户/模型限并发 |
| `maintenance` | 计数校准、清理 | 定时 |

重试只针对瞬时错误，指数退避加抖动；校验失败、权限失败不重试。

## 8. 缓存

- 公共内容详情：短 TTL + tag invalidation；
- 用户权限、封禁状态：极短 TTL 或每请求核验关键状态；
- 热门标签/榜单：物化结果；
- Cache key 包含资源版本和可见性上下文；
- 防击穿使用 request coalescing，空结果短缓存；
- 缓存失效不能成为权限绕过路径。

## 9. 安全中间件

处理顺序：Request ID → 安全 Header/CORS → Body limit → Auth → Rate limit → DTO validation → Authorization → Handler → Audit/metrics。

限流维度：

- 登录/重置：IP + identifier；
- 注册/上传：IP + user；
- 评论/互动：user + resource；
- 搜索：IP/user；
- Agent：user + plan + agent；
- 设备命令：user + device。

后台写操作均进入 `audit_logs`；日志为 append-only，任何查看敏感数据也建议审计。

## 10. 管理后台 API

- 查询必须分页、可按时间/状态/风险筛选；
- 批量操作设置数量上限并异步；
- 高风险操作二次确认、重新认证、原因必填；
- 管理员不能删除审计记录；
- 导出含 PII 的数据需特权 scope、审批和带水印/过期链接。

## 11. 配置与 Secret

使用类型化配置启动校验。环境变量只保存部署差异和 Secret 引用；业务开关放配置表/Feature Flag。

```text
DATABASE_URL
REDIS_CACHE_URL
REDIS_QUEUE_URL
S3_ENDPOINT / S3_BUCKET_*
JWT_KEY_ID / JWT_PRIVATE_KEY_REF
AGENT_RUNTIME_URL / INTERNAL_SERVICE_KEY_REF
OTEL_EXPORTER_OTLP_ENDPOINT
```

生产 Secret 使用云 Secret Manager 或 Vault；轮换不依赖重新构建镜像。

## 12. 后端测试

- Domain unit：状态机、权限、配额、计数；
- Repository integration：真实 PostgreSQL/Testcontainers；
- Contract：OpenAPI schema、Runtime callback、MQTT payload；
- API integration：认证、幂等、并发冲突、权限矩阵；
- Security：IDOR、CSRF、XSS、SSRF、压缩包、限流、token reuse；
- Load：Feed、详情、评论、上传意图、搜索；
- Chaos：Redis 短暂不可用、对象存储超时、LLM 429、MQTT 重连。

覆盖率不是唯一门槛；支付前虽无资金链路，但身份、权限、发布、文件和设备命令必须覆盖行为分支。
