# 产品规划与路线图

## 1. 产品定位

产品暂以“AI Hardware Hub”为工作名。核心不是做另一个泛内容论坛，而是让一个硬件创意具备完整生命周期：

```text
发现项目 → 获取资源 → 复现/二创 → 创建 Agent → 绑定设备 → 分享成果
```

差异化支点：

1. 内容对象是“可复现项目”，不只是帖子；支持版本、依赖、文件、许可证和适配硬件。
2. Agent 是“可运行资产”，有输入输出、工具权限、成本、版本、评测和运行日志。
3. 设备是“真实使用入口”，社区资产可一键装配到个人设备，但必须经过授权与安全策略。
4. 内容、Agent、设备三者以统一用户身份、权限、标签和数据分析连接。

## 2. 目标用户与核心任务

| 用户 | 核心任务 | MVP 价值 |
|---|---|---|
| 硬件爱好者 | 找方案、下载固件、排查问题 | 高质量项目页、资源下载、评论 |
| AI/Agent 开发者 | 发布 Agent、展示能力、获取用户 | 先发布 Agent 配置/说明，第二阶段可运行 |
| 内容创作者 | 写教程、沉淀影响力 | 编辑器、作品主页、互动和数据 |
| 普通设备用户 | 绑定设备、使用助手 | 第三阶段交付 |
| 社区运营者 | 审核、处理举报、组织专题 | MVP 管理后台 |
| 平台开发者 | 接入 API、创建工具/硬件 | 第四阶段开放平台 |

## 3. 产品原则

- 先形成内容供给和互动，再建设高成本 Agent Runtime 与设备云。
- 一个用户体系、一个资源模型、一个权限体系，避免重复建设。
- 默认最小权限；Agent 与设备执行真实动作必须显式授权。
- 项目资源必须标注许可证、版本、兼容硬件和风险提示。
- 用户可导出自己的内容、Agent 配置和设备数据。
- AI 生成或加工的内容必须可标识，关键审核结论不得仅由模型作出。

## 4. MVP 范围

### 4.1 必须交付

- 账号：邮箱注册/登录、邮箱验证、忘记密码、退出全部设备。
- 用户：公开主页、头像、简介、链接、作品/收藏/关注列表。
- 内容：动态、文章、项目；草稿、预览、发布、编辑、软删除。
- 项目：摘要、README、封面、硬件平台、许可证、仓库链接、资源附件。
- 互动：一级/二级评论、点赞、收藏、关注、站内通知、举报。
- 文件：图片/文档/压缩包预签名直传；类型、大小、配额和病毒扫描。
- 发现：首页信息流、最新/热门、分类、标签、站内全文搜索。
- 后台：用户封禁、内容下架、举报处理、标签/分类、审计日志。
- 基础质量：响应式页面、SEO、无障碍基本项、观测、备份、限流。

### 4.2 明确延后

- 私信延至 MVP+1：它会显著增加反骚扰、审核、未读一致性和实时基础设施成本。
- 推荐系统 MVP 使用规则分数，不训练个性化模型。
- Agent MVP 只展示“Agent 资产”；在线运行、RAG 和调度在第二阶段。
- 设备绑定、MQTT、OTA 和语音云链路在第三阶段。
- 视频转码、在线 IDE、代码托管、支付、商城不进入 MVP。

## 5. 核心对象

### Content

统一承载 `post`、`article`、`project`、`agent_listing`。公共字段支持作者、状态、可见性、统计和审核；各类型扩展字段单独存储。这样信息流、互动、举报和搜索无需做四套。

### Resource

上传文件不是内容本身。`file_objects` 记录存储对象和安全状态，`content_assets` 记录它在内容中的用途和排序。项目后续可增加 `project_releases`，把固件/PCB/代码包做成有版本的发行物。

### Agent

Agent 由不可变版本驱动。可发布的 Marketplace 条目指向一个 Agent Version；运行记录也固定引用该版本，确保审计与回放。

### Device

设备属于用户或组织，硬件唯一标识不直接暴露。绑定、凭证轮换、影子状态、遥测和 OTA 独立建模。

## 6. 关键用户流程与验收

### 发布项目

1. 用户新建草稿，选择项目类型与许可证。
2. 编辑 Markdown/富文本，上传封面和资源。
3. 前端保存草稿；服务端校验资源扫描状态和必填元数据。
4. 发布进入 `published` 或 `pending_review`。
5. 搜索索引和粉丝通知通过 Outbox 异步处理。

验收：重复点击发布不产生重复内容；未扫描文件不能公开下载；编辑后 URL 稳定；被下架内容作者仍可在中心看到原因。

### 互动

点赞/收藏采用幂等 PUT/DELETE；评论创建支持幂等键；计数最终一致但用户自己的当前状态必须读己之写。

### 文件上传

客户端请求上传意图 → 服务端返回预签名 URL → 客户端直传对象存储 → 完成回调 → Worker 校验 MIME/哈希/病毒 → 生成缩略图 → 文件变为可用。应用服务器不转发大文件。

## 7. 权限与信任等级

| 角色/状态 | 能力 |
|---|---|
| guest | 浏览公开内容 |
| member | 发布、互动、举报 |
| verified_creator | 更高配额、创作者标识、申请发布 Agent |
| moderator | 审核内容与举报，不可修改系统权限 |
| admin | 用户、配置、权限、审计管理 |
| service | 内部服务身份，按 scope 限权 |

创作者认证是业务状态，不应等同于系统管理员角色。封禁分登录禁用、发言禁用、上传禁用和设备禁用，避免只有“一刀切”。

## 8. 指标体系

### 北极星指标

每周产生有效价值的活跃创作者数（WVC）：一周内至少有一个被真实用户收藏、下载、运行或复现的已发布资产的创作者。

### 漏斗

- 获得：访客 → 注册转化率；
- 激活：注册 7 日内完成资料且发布/收藏/下载任一行为；
- 供给：周发布者、合格项目数、项目完整度；
- 互动：评论率、收藏率、关注转化；
- 留存：D1/D7/D30 创作者与消费者留存；
- Agent：运行成功率、P95 延迟、每成功任务成本（第二阶段）；
- 设备：绑定成功率、日在线率、语音成功率（第三阶段）。

护栏指标：举报率、确认侵权率、恶意文件率、审核 SLA、AI 成本/活跃用户、删除请求完成时长。

## 9. 分阶段路线

### Phase 0：基建与验证（2 周）

- 产品原型、领域词典、Monorepo、Compose、CI；
- 身份/内容/文件三个 PoC；
- 冻结 API 和数据库约定；
- 产出隐私政策、内容规范、开源许可证政策草案。

退出条件：staging 可自动部署；注册和预签名上传冒烟链路打通。

### Phase 1：MVP 社区（8–10 周）

- Sprint 1：账号、权限、用户资料；
- Sprint 2：内容草稿、编辑器、项目页；
- Sprint 3：文件处理、评论、点赞、收藏、关注；
- Sprint 4：首页、标签分类、搜索、通知；
- Sprint 5：管理后台、举报、审计、性能和安全加固。

退出条件：20–50 名种子用户完成 100 个有效内容资产；核心 API 可用性 ≥99.5%；无 P0/P1 安全缺陷。

### Phase 1.5：社区增强（4 周）

- 私信、专题合集、创作者认证、项目 Release、数据看板；
- 反滥用规则、内容质量评分、SEO 和增长实验。

### Phase 2：Agent 平台（8–12 周）

- Agent Builder、版本、工具目录、Secret Vault；
- 异步运行、流式输出、调度、日志、配额和成本账本；
- 文档知识库、混合检索、评测集与发布审核；
- Agent 市场先免费，验证留存后接计费。

退出条件：Agent 运行成功率 ≥98%；无越权工具调用；成本可归因到用户/Agent/任务。

### Phase 3：硬件生态（10–14 周）

- DNESP32S3 固件仓库和设备身份；
- 配网、绑定、MQTT、设备影子、命令确认、OTA；
- Voice Runtime 服务化、ASR/TTS、会话和 Agent 桥接；
- 小批量真实设备灰度、断网降级和远程诊断。

退出条件：绑定成功率 ≥95%；命令投递 P95 <1 秒（正常网络）；OTA 灰度可回滚；7 天稳定性测试通过。

### Phase 4：商业化（持续）

- 会员配额、Agent 订阅/分成、API 计费；
- 开发者门户、OAuth 应用、Webhook、组织空间；
- 硬件商城只在供应链、售后、合规能力就绪后启动。

## 10. 商业模式次序

1. 免费社区 + Pro 存储/私有项目/更高 Agent 配额；
2. Agent/知识库按量与订阅；
3. 开发者 API；
4. Agent 市场分成；
5. 硬件/配件商城。

不建议第一年同时做广告、电商和复杂双边市场。先证明内容供给、Agent 使用频率与设备留存其中至少两项。

## 11. 主要风险

| 风险 | 早期信号 | 缓解 |
|---|---|---|
| 范围过大 | 每个模块只有半成品 | 严格 Phase Gate，MVP 延后私信/Agent 运行/设备 |
| 冷启动 | 有网站无内容 | 邀请 20 位创作者，官方模板和挑战赛，先导入自有项目 |
| 文件与固件安全 | 恶意包、刷下载 | 隔离桶、扫描、哈希、限流、举报、签名固件 |
| Agent 越权/高成本 | 工具误调用、账单异常 | 最小权限、审批、预算、超时、审计、Kill switch |
| IoT 被劫持 | 共享密钥、伪造设备 | 每设备证书/密钥、安全启动、签名 OTA、轮换与吊销 |
| 数据合规 | 语音/私信被长期保存 | 数据最小化、明确同意、保留期、导出/删除、分级权限 |
