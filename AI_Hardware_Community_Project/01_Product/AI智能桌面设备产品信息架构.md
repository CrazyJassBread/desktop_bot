# MIMO AI 智能桌面设备产品信息架构

> 版本：MVP v0.3  
> 日期：2026-07-23  
> 当前约束：先验证 Web 与硬件联动，不接数据库

## 1. 产品定义

MIMO 是连接用户、AI Agent、ESP32-S3 和热敏打印机的智能桌面伴侣。
它不是“把聊天框装进硬件”，而是通过安静的屏幕反馈、语音、拍照、手势和纸面输出，
把数字信息变成可感知的日常体验。

核心价值：

1. 陪伴：待机时显示时间、天气、Todo 和柔和表情，激活时回应用户。
2. 学习：AI 问答、单词卡和学习计划形成轻量学习闭环。
3. 创造：OCR、AI Letter、手帐总结和自动简报把输入转成内容。
4. 行动：网页或手机可直接控制录音、摄像头、打印机、语言与电源状态。
5. 连接：自动消息 Agent 将新闻、天气、日历等信息变成可打印摘要。

## 2. MVP 用户

| 用户 | 核心场景 | 成功信号 |
|---|---|---|
| 学生/年轻创作者 | 学习、手帐、趣味互动 | 每周多次主动使用 |
| AI/硬件开发者 | 调试设备、验证 Agent 工作流 | Web 指令到设备 ACK 可追踪 |
| 礼物/陪伴型用户 | 晨间简报、彩蛋、信件 | 持续保留在桌面并形成习惯 |

## 4. 核心用户流程

### 4.1 首次连接设备

```text
注册/登录
→ 添加 MIMO
→ 手机与设备进入同一局域网
→ 设备显示一次性绑定码
→ Web 提交绑定码
→ 云端签发设备凭证
→ 设备建立 MQTTS
→ Dashboard 显示 Online
```

当前 MVP 使用独立设备模拟器代替配网和云端签发，用于先验证绑定后的产品体验。

### 4.2 AI 简报自动打印

```text
用户选择信息源和时间
→ Scheduler 触发 Message Bot
→ Agent 收集并过滤内容
→ LLM 生成 58mm 模板
→ 下发打印任务
→ 设备 ACK
→ 打印机完成并回传结果
```

### 4.3 AI Letter

```text
选择对象和语气
→ 输入关键词
→ AI 起草
→ 用户检查/修改
→ 数字发送或实体打印
→ 记录投递状态
```

### 4.4 手势

```text
摄像头帧
→ MediaPipe/端侧识别
→ 生成标准 gesture event
→ FSM 判断当前状态是否允许
→ 执行动作
→ 屏幕/网页同步反馈
```

## 5. MVP 验收标准

- 所有 10 个路由可以刷新并直接访问；
- 桌面端和 390px 手机端均可完成核心操作；
- Web 可以控制模拟设备录音、拍照、打印、语言、游戏、同步和电源状态；
- 模拟设备可以反向发送 V、Open Palm、Up、Down 手势；
- AI 简报、海龟汤、AI Letter 都能形成打印任务并收到完成回执；
- 数据库不可用时全部体验仍可运行；
- 设备真正断电与软关机在产品语言上明确区分。

## 6. 阶段路线

| 阶段 | 目标 | 关键产出 |
|---|---|---|
| M0（当前） | 可见、可玩、可联动 | Web MVP + 设备模拟器 |
| M1 | 接真实 ESP32-S3 | 配网、设备身份、MQTT、打印/摄像头/语音驱动 |
| M2 | 接 AI Runtime | ASR、LLM、OCR、Message Bot、任务调度 |
| M3 | 多用户长期运行 | 账号、PostgreSQL、对象存储、审计、监控 |
| M4 | 生态扩展 | 社区、Agent/模板市场、硬件商城、插件系统 |

## 7. 业务边界

- “AI 算卦/趣味预测”始终标注为娱乐，不做医疗、投资或人生决策承诺。
- AI Letter 生成后由用户确认，不自动代表用户发送。
- 摄像头默认本地优先；上传云端前必须有明确提示和权限。
- 远程“关机”默认是联网软关机。物理断电后若要远程开机，硬件必须增加常供电 PMIC、
  RTC/按键唤醒或辅助 MCU，不能仅依靠 ESP32-S3 应用软件实现。
